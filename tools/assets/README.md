# Asset Verification Tool

`manage_assets.py` verifies external rendering inputs without trusting the production loader. Its
default verification path is offline and read-only.

## Local Verification

```bash
python3 tools/assets/manage_assets.py verify --asset intel-sponza-base
```

The command checks:

1. the pinned glTF entrypoint and primary buffer SHA-256 values;
2. the archive-supplied license file size and SHA-256;
3. every glTF buffer/image reference and declared buffer/accessor range; and
4. the count, total bytes, and deterministic tree hash of the glTF URI closure.

The closure hash streams each file. For sorted paths it hashes:

```text
relative-path NUL decimal-size NUL file-sha256 LF
```

It does not hash unrelated authoring formats or renders in the 6.3 GiB extracted directory.

Use `--root PATH` to verify an extracted copy outside the repository. Use `--evidence PATH` to save
the JSON result generated by a run.

## Fetch and Install

Fetch is explicit, license-gated, and installs only outside the Git worktree:

```bash
python3 tools/assets/manage_assets.py fetch \
  --asset intel-sponza-base \
  --accept-license \
  --root /path/to/empty/external/asset-root
```

The archive cache defaults to `~/.cache/mini-engine/assets`; override it with `--cache`. A cached
archive is reused only after its exact size, SHA-256, and MD5/ETag are verified.

The official URL, filename, size, and response metadata are pinned in `assets/manifest.json`. Intel
does not publish an archive SHA-256. The checked-in SHA-256 is project-derived from a download made
on 2026-07-23 and is labeled accordingly; a future publisher download must match it exactly.

To install an already downloaded archive without network access:

```bash
python3 tools/assets/manage_assets.py install \
  --asset intel-sponza-base \
  --archive /path/to/main_sponza.zip \
  --root /path/to/empty/external/asset-root \
  --accept-license
```

Before extraction, the installer verifies archive size/SHA-256/MD5 and preflights every central
directory entry. It rejects absolute/traversing/backslash/drive paths, duplicate or case-colliding
names, encryption, symlinks, special files, unsupported compression, and entries that exceed
declared count, per-file, ratio, or total-byte limits. Extraction is streamed into a sibling
staging directory with actual byte limits. The complete glTF closure is verified in staging before
an atomic rename installs it. Any failure removes staging and leaves an existing empty destination
empty.

## Fixture Verification

The independent CI fixture has no external payload:

```bash
python3 tools/assets/manage_assets.py verify-gltf \
  tests/fixtures/gltf/phase0_scene.gltf \
  --expect tests/fixtures/gltf/phase0_scene.expected.json
```

The fixture oracle decodes binary positions, normals, texture coordinates, sparse overrides, and
indices. Bounds are computed from decoded positions rather than trusting accessor metadata. This
is still not proof that the legacy loader interprets the scene correctly: Phase 4 must run the
production CPU importer against the same expectations and add GPU upload readback evidence.
